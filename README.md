# Salda MCB Modbus (AHU) — интеграция для Home Assistant

Кастомная интеграция для Home Assistant, подключающаяся по **Modbus TCP** к контроллеру
вентиляционной установки **Salda MCB / miniMCB** (тепловые/вентиляционные установки с рекуператором).

Сгенерирована автоматически из полной таблицы регистров производителя
(`MCB-1.27-Modbus-table-2019-06-18-1.xlsx`) — покрывает **все 949 адресов**:

| Тип регистра | Кол-во | Платформа HA | Поведение |
|---|---|---|---|
| Holding Register (числовой диапазон) | 489 | `number` | Слайдер/поле для изменения уставок |
| Holding Register (перечисление) | 108 | `select` | Выпадающий список режимов |
| Coil | 80 | `switch` | Переключатель on/off |
| Discrete Input | 157 | `binary_sensor` | Статус/авария (только чтение) |
| Input Register | 104 | `sensor` | Измеряемая величина (только чтение) |

## Установка через HACS

1. HACS → Integrations → меню (три точки) → **Custom repositories**.
2. Добавьте URL этого репозитория, категория **Integration**.
3. Найдите "Salda MCB Modbus (AHU)" в списке интеграций HACS и установите.
4. Перезапустите Home Assistant.
5. **Настройки → Устройства и службы → Добавить интеграцию** → «Salda MCB Modbus (AHU)».
6. Укажите IP-адрес Modbus TCP шлюза, порт (обычно 502), Slave ID (обычно 1) и интервал опроса.

## Установка вручную (без HACS)

Скопируйте папку `custom_components/salda_mcb_modbus` в директорию
`config/custom_components/` вашего Home Assistant, затем перезапустите HA и
добавьте интеграцию через UI, как описано выше.

## Важно про адресацию Modbus

В таблице производителя все адреса регистров указаны "с 1" (1-based). По умолчанию
интеграция вычитает 1 при формировании запроса на шину (`ADDRESS_OFFSET = 1` в
`modbus_hub.py`), что соответствует поведению большинства Modbus TCP шлюзов/гейтвеев
для этого контроллера. Если после первого подключения показания сенсоров выглядят
сдвинутыми на 1 регистр (например, вместо температуры притока вы видите версию ПО),
поменяйте `ADDRESS_OFFSET` на `0` в файле `modbus_hub.py` и перезапустите HA.

## Обработка ошибок

- Если связь с контроллером пропадает, все сущности переходят в состояние
  **unavailable**, а в журнале Home Assistant появляется предупреждение с точным
  диапазоном регистров, который не удалось прочитать.
- Если недоступны абсолютно все диапазоны (устройство выключено/недостижимо),
  интеграция поднимает `UpdateFailed`, что отражается как ошибка обновления
  координатора на странице интеграции.
- Отдельные аварии/предупреждения самого AHU (перегрев, обрыв ленты ротора,
  неисправность датчика и т.д.) видны как `binary_sensor` с `device_class: problem`
  и попадают в диагностическую секцию устройства.
- Ошибки записи (например, попытка записать значение вне допустимого диапазона)
  выбрасывают исключение, которое Home Assistant показывает как уведомление о
  неудачном вызове службы (visible in Logbook/Notifications).

## Структура файлов

```
custom_components/salda_mcb_modbus/
├── __init__.py         # регистрация интеграции, платформы
├── config_flow.py       # UI-мастер настройки (host/port/slave_id)
├── const.py              # константы домена
├── coordinator.py        # DataUpdateCoordinator, батч-чтение по диапазонам
├── modbus_hub.py          # обёртка над pymodbus (Modbus TCP клиент)
├── registers.py            # автогенерированная карта всех 949 регистров
├── sensor.py                # Input Registers -> sensor
├── binary_sensor.py          # Discrete Inputs -> binary_sensor (+ аварии)
├── number.py                  # Holding Registers (диапазон) -> number
├── select.py                   # Holding Registers (enum) -> select
├── switch.py                    # Coils -> switch
├── manifest.json
├── strings.json
└── translations/
    ├── en.json
    └── ru.json
```

## Уровни доступа

Регистры уровня `Adjuster`/`Service` (тонкая настройка, PID-коэффициенты, калибровки)
помечены как `entity_category: config` или `diagnostic`, чтобы не загромождать
основную панель — они скрыты по умолчанию в карточке устройства под "Show more".
Регистры уровня `User` (режимы, уставки температуры, расписания) отображаются как
основные управляющие сущности.

## Известные ограничения / TODO

- Часть сервисных регистров (I/O map, коды калибровки) распознаны как обобщённые
  числовые поля (`number` 0-30 или 0-9999) — их семантика специфична для конкретной
  конфигурации AHU и требует сверки с руководством перед изменением.
- Регистры "history" (история аварий, 50 событий) читаются как обычные sensor —
  для удобного просмотра истории лучше использовать `logbook`/history-графики HA.
